# 003. 알림 조건이 데이터에 없는 스팬 이름을 보고 있어 한 번도 울리지 않았다

## 증상
"collector 수집 중단" 과 "detector 지연" 알림 조건이 활성 상태였고 열린 인시던트도 없었다. 그래서 정상이라고 판단했다. 실제로는 파이프라인 최상단이 끊겨도 알려줄 장치가 없었다.

2026-08-17 에 실제 장애에서 오진으로 이어졌다.

## 원인
조건의 NRQL 이 **존재하지 않는 스팬 이름**을 보고 있었다. `MessageBroker/Kafka/Topic/Produce/Named/events` 는 3일 동안 행이 0건이었다. 데이터가 0건이면 조건은 임계치를 넘을 일이 없고, 영원히 울리지 않는다.

**"열린 인시던트가 없다" 는 건강한 조건과 죽은 조건을 구분하지 못한다.** 그걸 근거로 검증됐다고 선언한 것이 판단 오류였다.

## 해결
조건을 실제 스팬 이름 기준의 비율로 다시 썼다(#285).

## 재발 방지
`scripts/newrelic-alerts.sh` 가 조건을 만들기 전에 **그 스팬이 데이터에 실제로 있는지 확인하고, 없으면 건너뛰고 종료 코드 1 을 낸다.** 예전에는 스크립트가 초록불로 끝났다.

알림 조건은 배포로 반영되지 않는다. `Alerts` 워크플로를 손으로 돌려야 서버 조건이 바뀐다.
