# 007. 시퀀스 룰 알림이 트랜잭션 밖에서 발행돼 서비스 맵이 끊겼다

## 증상
뉴렐릭 서비스 맵에 `detector → alert / responder / archiver` 간선이 안 그려졌다. 알림은 실제로 흐르고 있었고 컨슈머도 소비하고 있었다.

## 원인
진단을 두 번 틀렸다.

1. 처음에는 alert-service 가 트레이스 연결 0% 라서 컨슈머가 깨졌다고 봤다. 트랜잭션 이름까지 쪼개 보니 520건이 전부 `ServletRequestListener/requestInitialized`, 즉 **헬스 프로브**였다. 프로브는 부르는 상위가 없으니 부모가 없는 게 정상이다.
2. 다음에는 컨슈머가 헤더를 안 받는다고 보고 세 서비스를 고쳐 배포했다. 간선은 여전히 안 생겼다. 트레이스를 열어 보니 **루트가 alert 자신**이었다. 헤더가 애초에 메시지에 없었다.

진짜 원인은 발행 쪽이었다. `CorrelationProcessor` 의 발행 경로가 둘인데 한쪽이 트랜잭션 밖이었다.

- `processRecord` 안 발행(점 룰) → 트랜잭션 안 → 헤더 실림
- `flushQuietHosts` 발행(시퀀스 룰 R1·R2) → **WALL_CLOCK punctuator 라 트랜잭션 밖** → 헤더 안 실림

트랜잭션이 없으면 프로듀서 계측이 헤더를 통째로 넣지 않는다. 받는 쪽을 고쳐도 소용없다.

## 해결
flush 할 것이 있을 때만 `KafkaTraceLink.traced()` 로 트랜잭션을 연다(#264). 컨슈머 쪽 `accept` 도 같이 있어야 이어진다(#261). 컨슈머 변경은 필요했지만 그것만으로는 부족했다.

## 재발 방지
진단 순서를 고정했다.

1. `kafka-get-offsets.sh` 로 알림이 실제로 흐르는지
2. 서비스 로그로 소비되는지
3. **트레이스 최상단이 누구인지** - 컨슈머 자신이 루트면 헤더가 없는 것이고, 그때는 받는 쪽이 아니라 **보내는 쪽**을 본다

헤더 확인은 끝 오프셋을 집어서 본다. `--from-beginning` 은 고치기 전 옛 메시지를 보여줘 오판한다.

부모 없는 트랜잭션을 연결 실패로 읽지 않는다. 트랜잭션 이름까지 쪼개서 본다.
