# 010. events 토픽만 Protobuf 로 바꾼다

- 날짜: 2026-08-04
- 상태: 채택

## 배경
> 이벤트 한 건마다 12개 필드명이 값과 함께 실리고 있었다. 정보량이 0인 바이트가 단말 수만큼 곱해지고, 브로커 디스크와 컨슈머 파싱에 다시 곱해진다.

## 결정
`events` 토픽의 값만 Protobuf 로 바꾸고, 스키마는 `event-schema` 모듈의 `.proto` 한 벌로 모은다. **수집 API 가 받는 본문(JSON)은 그대로 둔다.**

## 근거
**수집 API 입력을 JSON 으로 두는 이유**:
> 수집 API 가 받는 본문은 검증 전 원본이라 JSON 을 유지한다. 여기에 스키마를 강제하면 거부해야 할 데이터를 받지도 못해 무엇이 왜 잘못 들어왔는지 볼 수 없다.

**Avro + 스키마 레지스트리를 버린 이유**:
> Avro 가 아니라 Protobuf 인 이유는 크기가 아니라 스키마를 어디 두느냐다. Avro 의 강점은 카프카에서 스키마 레지스트리를 전제로 하는데, 지금 규모에서 브로커 옆에 컴포넌트를 하나 더 띄우는 비용이 얻는 것보다 크다.

**필드 번호 설계**: 필드 1~12 를 16번 미만에 둔 것은 의도다. 16번부터 태그가 1바이트에서 2바이트로 늘어난다. 번호를 재사용하면 옛 데이터를 엉뚱한 필드로 읽으면서 에러도 안 난다.

**`type` 을 proto enum 으로 안 둔 이유**: 에이전트와 ClickHouse 가 모두 이 값을 문자열로 다룬다.

## 결과/영향
- **바이너리라 Kafka UI 로 본문을 못 읽는다.** 대신 레코드 헤더에 `schema-version`, `event-type`, `tenant-id` 를 실어 본문을 풀지 않고도 거를 수 있게 했다. Kafdrop 을 UI for Apache Kafka 로 교체한 것도 이 맥락이다.
- event-schema 를 여섯 서비스가 전부 참조한다. 여기를 고치면 전 모듈을 다시 구워야 한다. CD 의 공통 파일 목록에서 빠져 있어 이미지가 안 구워진 적이 있다(`docs/design-docs/failures/004-*`).
- 감소율은 계산치(39~54%)를 그대로 쓰지 않았다. 전환 전 형태를 proto 의 JSON 매핑으로 대신하면 빈 필드가 빠져 실제보다 작게 잡히고 감소율이 과장된다.
- 운영에 올렸던 페이로드 크기 측정 코드는 되돌렸다. 측정이 던지면 발행은 끝났는데 `publish` 가 false 를 돌려줘 에이전트가 그 배치를 다시 보낸다. 측정 코드가 중복 이벤트를 만들 수 있었다.
