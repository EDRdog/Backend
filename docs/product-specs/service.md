# EDRdog 기능 명세

지금 구현된 것 기준이다. 아직 없는 것은 상태에 적었다. 검증 가능한 기준은 `docs/requirements/`, 왜 이렇게 정했는지는 `docs/design-docs/decisions/`.

## F1. 엔드포인트 행위 수집

기기 안에서 벌어지는 프로세스·네트워크·파일·스크립트 실행을 관찰해 서버로 보낸다.

| | |
|---|---|
| 대상 플랫폼 | macOS, Windows |
| 이벤트 종류 | `process`, `network`, `file`, `script`, `dns`, `l7` |
| 수집 방식 | 폴링이 아니라 커널 이벤트 구독 (예외: macOS 네트워크) |
| 상태 | macOS 실기기 확인됨 / Windows 실기기 미검증 |

공격 도구는 짧게 실행되고 사라져서, 주기 조회로는 조회 사이에 뜨고 사라진 프로세스를 놓친다. 그래서 구독을 유지한다.

## F2. 등록과 조직 구분

| | |
|---|---|
| 등록 | 조직별 enroll secret 으로 등록하고 node_key 를 받는다 |
| 이후 인증 | `X-Node-Key` 헤더 |
| 조직 구분 | 서버가 node_key 로 푼다. 엔드포인트가 보낸 조직 태그는 믿지 않는다 |
| 서버 신뢰 | 에이전트가 서버 인증서를 고정(pinning)한다 |
| 설치 | 대시보드가 만든 설치 링크(기본 TTL 24시간). enroll secret 을 사람 손에 쥐여주지 않는다 |
| 상태 | 구현됨 |

## F3. 공격 시퀀스 판정

한 건이 아니라 여러 행동의 순서로 판정한다. host 별 5분 윈도우.

| 룰 | 무엇을 잡나 | MITRE |
|---|---|---|
| R1 | 오피스 문서가 shell 을 띄움 | T1059 |
| R2 | 외부에서 받아온 파일을 실행 | T1105 + T1204 |
| R3 | 임시나 다운로드 경로에서 스크립트 실행 | T1059 |
| R4 | 자동실행 경로에 파일 생성 | T1547 |

R2 가 심각도가 가장 높고, 프로세스 관점과 네트워크 관점을 이어야 성립한다. 수집기를 하나로 합친 이유가 이 룰이다.

판정은 도착 순서가 아니라 **엔드포인트에서 찍힌 발생 시각**으로 한다. 상태: 구현됨.

## F4. 알림

판정이 나면 조직별 Slack Incoming Webhook 으로 보낸다.

| | |
|---|---|
| 수신 대상 | 호스트 소유자의 개인 webhook 이 있으면 그쪽, 없으면 조직 webhook |
| 중복 억제 | 수신 대상 + host + ruleId 기준 60초 |
| 억제 기준 시각 | 처리 시점이 아니라 알림에 실린 이벤트 시각 |
| 전역 폴백 | 두지 않는다 (조직 격리) |
| 상태 | 구현됨 |

## F5. 대응 (프로세스 종료)

| | |
|---|---|
| 명령 종류 | `kill_process` 하나. 서버는 대상 문자열만 보낸다 |
| 전달 경로 | 에이전트가 하트비트를 보낼 때 받아 간다. 서버가 기기에 접속하지 않는다 |
| 실행 조건 | 자동으로 쏘지 않는다. 대시보드에서 사람이 확인해야 한다 |
| 응답 | `POST /api/responder/kill` 이 202 와 명령 id 를 바로 준다. 결과는 조회 |
| 대상 해석 | 조치하는 그 순간에 프로세스 목록을 다시 훑는다. 부분 일치는 쓰지 않는다 |
| 안전장치 | 자기 자신과 PID 1 은 죽이지 않는다. 일부만 종료되면 FAILED |
| 격리(isolate) | **미구현.** 관리 채널 예외와 자동 해제 타이머가 함께 있어야 안전해서 미뤘다 |
| 상태 | 프로세스 종료만 구현됨 |

## F6. 저장과 조회

| | 담는 것 | 보존 |
|---|---|---|
| ClickHouse `events` | 이벤트 원본 | 7일 |
| ClickHouse `alerts` | 판정 기록 | 90일 |
| ClickHouse `events_hourly` | 시간·타입별 건수 롤업 | 180일 |
| MySQL | 계정, 조직 설정, 알림·인시던트 처리 상태 | 삭제 안 함 |
| S3 / MinIO | 만료 전 원본(Parquet) | **기본 OFF** |

알림 목록은 ClickHouse 의 판정 기록 위에 MySQL 의 처리 상태를 겹쳐서 보여준다.

롤업을 둔 명분은 속도가 아니라 보존이다. 원본이 7일인데 침해는 발각까지 몇 주가 걸린다.

## F7. 대시보드 API

프론트엔드가 쓰는 조회 API. 세션 인증(Bearer).

| 묶음 | 경로 | 주는 것 |
|---|---|---|
| 인증 | `/api/auth/*` | 가입, 로그인, 로그아웃, 내 정보 |
| 알림 | `/api/alerts/*` | 목록, 요약, 시계열, 상세, 계보, 트리아지, 대응 실행·조회 |
| 이벤트 | `/api/events/*` | 목록, 상세, 요약, 추세, 국가별 지도 |
| 호스트 | `/api/hosts/*` | 목록, 요약, 프로세스 트리 |
| 인시던트 | `/api/incidents/*` | 목록, 상세, 타임라인, 상태 변경 |
| 검색 | `/api/search` | 통합 검색 |
| 인텔리전스 | `/api/intelligence/*` | 상관 조회, DNS 실시간 조회, 토폴로지 |
| 운영 | `/api/operations/health` | 의존성 상태 |
| 설정 | `/api/tenant/*`, `/api/me/*` | webhook, enroll secret, 담당 호스트 |

상태: 구현됨.

## 비기능 요건

| | |
|---|---|
| 조직 격리 | 모든 조회 질의에 tenant 조건이 강제로 붙는다 |
| 페이지네이션 | OFFSET 상한이 있다. 넘으면 400 이고 from/to 로 좁히게 한다 |
| 관측 | 운영은 뉴렐릭 자바 에이전트, 로컬은 otel-lgtm |
| 수집 가용성 | 조회가 몰려도 수집은 멈추지 않아야 한다 (입구를 분리한 이유) |
| 유실 | 현재 알려진 유실 지점 3곳이 있다. `docs/exec-plans/tech-debt.md` |
