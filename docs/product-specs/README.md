# 제품 명세 (PRD)

무엇을 만드는지와 왜 만드는지. 어떻게 만드는지는 `docs/design-docs/`, 검증 가능한 기준은 `docs/requirements/`.

지금은 서비스 전체 설명이 루트 `README.md` 에 서술형으로 들어 있다. EDR 이 무엇인지, 백신과 무엇이 다른지, 수집·판정·대응 각 단계가 무엇을 하는지가 거기 있다.

기능 명세는 `service.md` 에 있다. 기능 묶음이 더 늘어나면 여기에 `<기능>.md` 로 추가한다.

## 탐지 룰

| 룰 | 무엇을 잡나 | MITRE 기법 |
|---|---|---|
| R1 | 오피스 문서가 shell 을 띄움 | T1059 |
| R2 | 외부에서 받아온 파일을 실행 | T1105 + T1204 |
| R3 | 임시나 다운로드 경로에서 스크립트 실행 | T1059 |
| R4 | 자동실행 경로에 파일 생성 | T1547 |
| R5 | 낡은 TLS(SSL 3.0, TLS 1.0, 1.1)로 맺은 연결 | T1573 |

### 데이터 룰 (Sigma 부분집합 파일)

R1~R5 말고 이벤트 하나로 판정되는 룰은 코드가 아니라 파일이다. 룰을 더하거나 고치는 데 배포가 필요 없다.

- 형식은 Sigma 의 부분집합이다. 룰 하나가 파일 하나이고, 알림의 `ruleId` 는 파일의 `name` 을 대문자로 바꾼 값이다.
- 기본 28개를 SigmaHQ 공개 룰에서 가져와 번들한다. 목록, 출처, 지원하는 문법은 `detector-service/src/main/resources/rules/README.md`.
  종류는 Windows 명령행(LOLBin, 자격증명 덤프, 랜섬웨어 준비, 방어 무력화), macOS 명령행(권한 상승, 지속성, 방어 무력화), DNS(Tor, 파일 공유), 파일(mimikatz, lsass 덤프)이다.
- 대응은 보수적이다. 프로세스 종료(kill)를 권고하는 것은 명백히 악성인 5개(mimikatz, SAM 덤프, 섀도 복사본 삭제, 전체 백업 삭제, procdump lsass)뿐이고 나머지는 알림만 보낸다.
- 운영에서는 ConfigMap 으로 마운트해 30초마다 다시 읽는다. 깨진 파일은 이전 룰이 유지된다.

R2 가 이 시스템에서 심각도가 가장 높고, 프로세스 관점과 네트워크 관점을 이어야 성립한다. 수집기를 하나로 합친 이유가 이 룰이다(`docs/design-docs/decisions/008-own-go-agent.md`).
