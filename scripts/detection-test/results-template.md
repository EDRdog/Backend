# 탐지 시험 결과 (템플릿)

`run.sh --run` 이 이 모양으로 결과 파일을 만든다. 손으로 적을 때도 같은 칸을 쓴다.
측정 조건을 반드시 같이 적는다(이 레포 수치는 로컬 합성이 많아, 조건이 없으면 근거가 못 된다).

## 측정 조건

- host:
- macOS 버전:
- 에이전트 바이너리 sha256:
- 서버(api): http://localhost:8084 (로컬 kind + bootRun)
- detector 마지막 기동 시각(UTC):  (시작까지 경과 초, 600 이상이어야 한다)
- 시작 전 10분간 이 host 의 알림 수:  (0 이 아니면 배경 오탐이 섞인 것)
- 시나리오 간격 / 판정 대기 / 조회 주기: 330s / 120s / 3s
- 응답(kill) 시험: 켬/끔

## 탐지율

- 분모 = 전체 시나리오 16개 (탐지 기대 10 + 미탐 기대 6).
- 분자 = 알림이 한 건이라도 난 시나리오 수.
- 탐지율 = 분자 / 분모. 기대값은 10/16 = 62.5% 언저리다.
- EDR-SE-01 의 "알려진 악성파일 70%" 와 직접 비교하지 않는다(아래 계획 문서의 매핑 참고). 이 수치는 행위 기반 탐지 커버리지다.

## 칸 뜻

- 수집: O 면 ClickHouse(api-service 조회)에 그 행위 이벤트가 들어왔다. X 면 센서나 적재에서 끊겼다.
- 알림 룰: 상관 창 안에 난 알림의 ruleId 목록. 비면 미탐.
- 응답: --respond 를 줬고 kill 권고 알림의 대상이 이 시나리오 경로일 때만. PENDING/KILLED/NO_MATCH/TIMEOUT/FAILED 또는 건너뜀.
- 판정: 기대와 실제가 맞으면 탐지/미탐(예상대로), 어긋나면 미탐/탐지(예상 밖).
